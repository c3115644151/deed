# 文档索引与规矩

对着什么找什么，一篇就够。下面五份是**权威**，其余都不是：

| 文件 | 说什么 | 谁改 |
| --- | --- | --- |
| [`../README.md`](../README.md) | 对外唯一入口：它是什么、怎么装、怎么接、站在哪一格 | 定位变了才改；改前先在这里对齐 |
| [`../AGENTS.md`](../AGENTS.md) | 维护者规则：谁能改什么、提交前跑什么 | 维护者 |
| [`DESIGN.md`](DESIGN.md) | 行为权威：事件形状、折叠规则、判据、不变式 | 改行为先改它，再动代码 |
| [`INSTALL.md`](INSTALL.md) | 装、接、升级、卸、常见故障 | 命令或产物变了就改 |
| [`../HANDOFF.md`](../HANDOFF.md) | 现状、下一步、没做的 | 每轮收尾 |

辅助材料两件：

- [`research.md`](research.md)：对照与出处，「站在哪一格」那一节的底稿。
- [`deed-architecture.html`](deed-architecture.html)：架构图源文件；`architecture.png` 是它的一张截图，给 README 用。

演示数据在 [`../examples/`](../examples/)，不算文档：`examples/contract/NOTES.md` 是那份示例账本的说明。

## 一条规矩：新增文档先问

这个仓库**不再累加文档**。要新起一份之前，先回答三个问题：

1. 它说的是哪一格的**事实**？如果这格已经有主人（见上表），它应该并进那份，而不是并排一份。
2. 它会被谁读？读完会**改变哪一个动作**？答不出动作的，是过程材料，不进仓库。
3. 它会多久过期？跟着代码走的写进 DESIGN 或注释；跟着环境走的写进 INSTALL；一次性的留在 issue、聊天或本地临时目录。

三条都过了再新建，并在这一页登记一行。调研、截图、对话记录、临时脚本都不进文档区：它们是过程材料，用完就该消失，
需要留的只是结论（写进上面那五份之一）。

## 图的规矩

`deed-architecture.html` 是单文件、离线、可交互，**手维护**：改图就直接改 HTML。
生成它用过的 archify 规格留在本机 `.archify/`（`.gitignore` 里，不随仓库走），所以 clone 下来拿到的是**手维护的源文件**；
当初跑过的四门回执对不上现在的字节，已经删掉，不留过期证据。

改图时：

- 只用内联字体与内联脚本，不加外部资源（离线打开不能有半张图缺字）。
- 改完在浏览器里真开一次：1440 宽无横向溢出，暗色主题下文字对比度够。
- 改完重拍 `architecture.png`（README 引用它），两张图说的是同一件事。
- 节点上写的名字必须是代码里真有的：事件类型、命令、文件。代码删了，图也要删。
