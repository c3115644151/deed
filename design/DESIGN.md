# deed 设计（唯一权威）

版本 2。这份文件定义 deed 是什么、按什么规则运转。代码与它冲突时，改代码。

## 1. 它是什么

deed 是一个工作区里的**议事与执行机制**：把"怎么说事、怎么做事、怎么算完"固定下来，使它不依赖参与者的自觉。

它不持有项目概念。文档契约、测试命令、架构约束、分支规矩属于宿主；deed 只按声明的顺序调用它们、汇总结果、把失败说清楚。

它与规格驱动工具（OpenSpec 一类）的差别不在对象，而在**驱动方式**：规格驱动靠"人记得读文档"，机制驱动靠"机制每轮都在场"。

## 2. 六个概念，三层结构

| 概念 | 定义 | 承载 |
|---|---|---|
| **轮次 turn** | 用户与 agent 的一次往返 | 机制的心跳。每轮一条，无条件、与他事无关 |
| **会话 session** | 轮次区间：首轮即开期，签收或强制归档即结束 | 讨论脉络、待裁项、若干段 |
| **段 segment** | 一个判决周期 | 一段独立的任务清单、审查强度、判决结论 |
| **任务 task** | 一个承诺 | 做完的标准 + 证据 |
| **审查 review** | 审查者按任务书判断 | 合格/不合格 + 依据 |
| **签收 sign** | 用户接受"这一期到此为止"并封存会话 | 唯一的正常结束方式 |

状态（讨论 / 执行 / 验收）不是对象，是**读数**，由内容推导，不由人设定。

三层各管一件事：会话聚焦"本期所关心的事"，段聚焦"这一批"，任务聚焦"这一件"。视野里只有当前段；历史段折叠成一行，数据一条不删。

**段不进入讨论态。** 会话的讨论脉络是连续的，不能被段切分；段是讨论中不断切出来的执行单元。

## 3. 三条不变式

1. **机制在场**：任何必需动作都不依赖 agent 记得。记轮要有物理钩子，状态要有推导，会话和段由动作推动。
2. **判决权不可代理**：判决与签收只由用户做。系统可以催、可以让代价可见，不能替人判。
3. **事实唯一且可追**：同一事实只有一个主人；每个结论都能追到谁、何时、基于什么。

冲突时优先级：2 > 1 > 3。

## 4. 八条硬规则

1. **首轮即开期**：写入第一条轮次时建立会话（编号按顺序 S01、S02，名字在签收时补），没有"创建会话"这个动作。反过来，**只有轮次能开会话**：会话已收口时，任何其它动作都被拒，不许自己发明一期。
2. **段由判决推进，不许手动切**：当前段被判过后，下一条任务写入时才开新段（惰性）。禁止手动切段——切段会变成逃生舱。
3. **段只折叠不删**：视图重置只发生在"显示什么"，不发生在"数据还在不在"。
4. **待裁项归会话，不归段**：待裁项是"还没定的问题"，跨段存活；处置只有两种——用户裁定（落成任务，进当前段）或 agent 撤回。签收前必须清零。
5. **审查门槛由路径声明，不由感觉**：哪些路径被改就必须过审查，写在宿主的 config 里；内核不猜。任务未声明触及路径时按"需要审查"处理（保守）。路径先归一化（反斜杠转正斜杠、去掉开头的 `./`）；带 `..` 或写成绝对路径的，一律按"要审"处理——不能借路径写法逃出门槛。
6. **前折叠，后落盘**：任何写动作先在内存里把账本折一遍，折得动才追加这一行。被拒的动作一个字也不进账本，工作区不会因为一次手滑变成折叠不了的坏账。
7. **编号与事实不许撞车**：任务与待裁项共用命名空间，同一个会话里 `T1`、`A1` 都不许出现两次；编号由折叠后的账本给（取最大值 +1），不由进程各自数。并发写入靠 `.deed/log/lock` 串行。
8. **签收需结清**：当前段已判过、无未做、无做完未判、待裁为零、没有指到工作区外的证据，才允许签收。未签收不允许走正常结束；异常结束走强制归档并打标签。

## 5. 生命周期

```
init（写 config + 记第一轮）
  → 讨论（轮次、范围、待裁项）
  → 段开始（第一条任务写入）
  → 执行（任务：todo → done）
  → 审查（按门槛，审查者出结论）
  → 判决（用户：整段通过 / 打回指名）
  → 判过 → 段封存 → 下次写任务自动开新段
  → 打回 → 段重开 → 补完再判（该段既有审查结论作废）
  → 全部结清 → 签收 → 会话封存 → 自动开新期
```

强制归档（shelve）：未结清而必须放下时使用，打异常标签，不占当前焦点；未结任务持续可见（`deed state` 的"欠着"一行），直到回去结清。

打回之后该段的既有结论作废（记 `voidedAt` 与 `voidedBy`），段重新打开；此后再没人审过的那一段**判不动**——不是"没有结论"而是"结论作废"，两者的下一步不同（前者出任务书，后者重审）。

## 6. 判据表

**状态读数**

| 读数 | 条件 |
|---|---|
| 讨论 | 当前段为空，只有轮次与待裁项 |
| 执行 | 当前段存在未做，或做完未判 |
| 验收 | 当前段已判过、待裁为零，无未做未判 |

**判决（段级，用户）**

- 可判前提：该段无 todo；在案的审查结论为合格；没有"结论早于最后一次交付"的段；证据全部钉在工作区内。
  **免审段里若落了不合格结论，同样挡住判决**——结论已经落了，就是事实。
- 在案的结论只能被"打回 + 重审"替换：`review` 拒绝在案不合格之上落 pass（先 `judge --rework`），
  也拒绝在段里还有 todo 时落任何结论（结论只回答已交付的内容）。
- `pass`：该段任务全部转为已交付；段封存；下次写入开新段。
- `rework`：指名的不合格任务退回 todo，证据清空，该段既有审查结论作废（记 `voidedAt`，不删行），段重新打开。只允许打回**最新那一段**：更早的段后面还有别的段时被拒，否则会出现两段同时开着；点名到别的段的任务同样被拒。

**签收（会话级，用户）**

- 当前段已判过；无 todo；无 done 未判；待裁为零。
- 记录用户原话；可同时给会话定名。

**审查门槛**

- 门槛是账本事实，不是磁盘文件：`review.required/exempt`、`gates`、面板端口都以 `config.change` 事件写进账本（`fold` 把它们折成 `doc.config`），`.deed/config.json` 只是它的镜像。判据读折出来的那份，不读文件；两边不一致时 `deed state` 标出来、`deed verify` 报"门槛对不上"并 exit 1。手工改文件改了什么都不算数，收下它要走 `deed init --force --why "为什么改"`——门槛这条预期因此和别的事实一样可追。
- 段内任一任务触及门槛里 `review.required` 的路径，或任一任务未声明路径 → 该段必须审查。
- 全部触及 `review.exempt` 且无未声明 → 免审。
- 审查结论先出任务书（`deed review`，只写 `.deed/review/<段>-<时间戳>.md`，不产生事件），再由审查者落结论（`deed review --by … --verdict pass|fail`）。**每个结论都当场写一份新任务书**，与结论同时入账的是它的 sha256（`briefDigest`）；任务书不覆写，同一段审两次就有两份，账本记得每次读到的是哪一份。账本只记路径与指纹，任务书正文不入账；`deed verify` 重算核对——被改过、丢了、或账本没记指纹的，那份结论不算数（打回后再审一次，任务书当场重写）。
- 门槛读"声明 ∪ 实动"：`task.done` 落盘前先给工作区拍快照、算出这一条改过哪些文件（`changed`），门槛同时看任务声明的路径与这份实动清单。声明写少了逃不出去。
  基线的内容指纹留在 `.deed/workspace.json`（第一次 `task done` 时生成，之后每次交付刷新）；它只是"上一次交付时长什么样"的记录，丢了最多少知道一次动过什么，不丢事实。
- 证据要么钉住一份内容（`--digest <工作区里的普通文件>`），要么就被 `judge`／`sign` 拦下；`deed verify` 把"没钉内容"单列一档，不混在"过期"里。

## 7. 动作表

| 动作 | 谁 | 作用 |
|---|---|---|
| `deed init` | 人 | 首次：把门槛写进账本（三条 `config.change` 基线）并记第一轮；`--force` 改门槛要带 `--why`，改动同样记为 `config.change`，文件只是跟着写出来的镜像 |
| `deed tick` | 机制 / agent | 记一轮（谁、说了什么、做了什么）；只有它能开会话 |
| `deed task add/done/defer/drop` | agent | 承诺、交付（done 必须带证据）、延后、放弃（后两者带理由） |
| `deed ask` | agent | 把模糊需求变成待裁项，必须写清"我理解成什么、为什么不确定" |
| `deed review` | 审查者 | 出任务书；带 `--by --verdict` 时落结论与依据 |
| `deed judge` | 用户 | 对当前段（或 `--segment` 点名的段）：`--pass` 通过 / `--rework T1,T2 --why …` 打回 |
| `deed sign` | 用户 | 结清并封存会话，自动开新期 |
| `deed shelve` | 用户 | 强制归档，打异常标签 |
| `deed state` | 任意 | 打印当前读数、当前段、下一步·谁 |
| `deed verify` | 任意 | 重算证据与任务书指纹：证据分"路径越界 / 证据过期 / 没钉内容"，任务书分"越界 / 对不上 / 不在了 / 没指纹"（不改账本） |
| `deed doctor` | 任意 | 逐行体检账本；坏行指出行号与修法 |
| `deed gate [名字…]` | 机制 / 人 | 按 config 里 `gates` 的顺序跑宿主的门命令，一条不过就停，报名字与退出码 |
| `deed serve` | 任意 | 只读面板（SSE 自刷新） |

没有 `start`、没有 `park`、没有 `back`。会话不由人建，就没有"建"的命令。

## 8. 数据形态

**唯一权威是追加账本**：`.deed/log/YYYY-MM.jsonl`，一行一个事件，随工作区提交（它是团队共享的事实）。

**状态是投影**：`deed state` 与面板都从账本即时折算，可随时重算，坏了就删。

理由不是存储偏好，而是不变式 1 的推论：如果状态是一份可变全局文件，agent 每轮都要维护全局一致，机制就重新依赖自觉，并发也立刻打架。追加天然廉价、并发安全、可重算。

事件一律带两件事：`at`（UTC 时刻，只来自写入那一刻）与 `s`（落在哪个会话）。开期的那条轮次不带 `s`——它就是这一期的出生证明，指回去会让这一行单独读不懂。

事件类型：`turn`、`task.add`、`task.done`、`task.defer`、`task.drop`、`ask.raise`、`ask.resolve`、`ask.withdraw`、`review.log`、`judge.pass`、`judge.rework`、`sign`、`shelve`、`config.change`。

**身份是约定，不是鉴权**：`who`、`by`、`sign` 记的是自述。账本保证"谁说过什么"可回溯，不保证"说的人是谁"——它不是签名链。

**路径以正斜杠入账**（`core/fold.mjs`，不是 `core\fold.mjs`）：账本会跟着工作区去别的机器。

**证据的内核语义**：一句声明、谁钉的、什么时候、钉在工作区里哪个文件（`digestPath`）、那个文件当时的 sha256（`digest`）。
"树变了证据就过期"是通用机制，保留；证据内容是否真的证明事做完了，由宿主的门判断；"这证据指向的东西还在不在这个工作区里"，由 `verify` 判断。任务书同理：它在账本外、是可被改的普通文件，账本只记它的 sha256，`verify` 对不上就说明这份结论读的不是当初那份。

**坏账的唯一人工修法**：`deed doctor` 指出第几行坏了，那一行整行移到 `.deed/log/rejected/` 并记下为什么；其它行一个字不动，缺的那件事用正常命令重做一次。不许手写补账。

## 9. 宿主接口

`.deed/config.json`（写法；真正进判据的是 `deed init` 把它记成的账本门槛）：

```json
{
  "review": { "required": ["src/**", "apps/**"], "exempt": ["docs/**"] },
  "gates": { "commit": ["<命令>"], "check": ["<命令>"] },
  "board": { "port": 7317 }
}
```

deed 对门只做两件事：按顺序跑、把失败说清楚。门的内容属于宿主——它不知道一个门过了意味着什么。

## 10. 已知代价（不掩盖）

1. **滚动速度由用户的判决节奏决定。** 用户不判，段不切，活全压在当前段。这是"判决权不可代理"的代价，系统只能让代价可见（当前段任务数、跨度、未判数）。
2. **审查门槛依赖宿主声明。** 声明写得松，机制就有洞；声明不写时内核保守（要审）。
3. **账本随仓库提交会增长。** 按月分片，一行一轮；这是可追溯的必要成本。
4. **没有跨会话任务池。** 结清前不许换期；必须换期时走强制归档，账留着。
5. **追加要抢锁。** 并发写是串行的：最多等 10 秒，锁里写着持有者的 pid 与开始时间；持有者凭 pid 判活——活着就不夺，死了立刻接手，无 pid 的锁存在超过 250 毫秒才算残留；这是"折叠后才落盘"的代价，换来的是账本永远折得动。
6. **坏账不会自愈。** 磁盘被人手改坏之后，deed 只会指出来，不会自动修——因为自动修就得猜哪一行才是真的。
